# Plan: Unlock & operationalize all 4 locked dashboard tabs

## Root cause (why tabs are locked)
`frontend/src/Sidebar.tsx` renders the 4 "Pipeline" tabs (Enrichment, Scoring, Export, Settings) from a `FUTURE` array as `<button disabled className="nav-pill disabled">` with a `LockIcon` and no `onClick`. There are **no component files** and **no backend endpoints** for any of them. The DB tables (`enrichments`, `scores` — incl. `llm_summary`) already exist but are never written to. The `jobs` table already supports `type ∈ scrape|enrich|score`. LLM config fields (`llm_base_url/api_key/model`) exist in `app/config.py` + `.env` but are **empty**, and there is **no LLM code or `openai` dependency**.

Your locked-in decisions: **OpenAI-compat (paas/v4) LLM**, **Functional MVP all tabs**, **Browser-only enrichment**, **Settings = config viewer + editable scrape knobs + data mgmt + LLM console**.

## LLM wiring (GLM via zai plan key)
- Add `openai` to `requirements.txt`; install via `.venv/bin/pip`.
- Populate `.env`: `LLM_BASE_URL=https://api.z.ai/api/paas/v4`, `LLM_API_KEY=<…tOJs key from ~/.zcode/v2/config.json provider["builtin:zai"].options.apiKey>`, `LLM_MODEL=glm-4.6`.
- New `app/scoring/llm.py`: thin `OpenAI(base_url=…, api_key=…)` client + `explain_score(...)` and `llm_ping(prompt)` helpers. Graceful no-op (returns `None`, logs) when key/endpoint unset. Matches CLAUDE.md rule "OpenAI-compatible client, no hardcoded OpenAI."
- Model-id note: `glm-4.6` is the default; if the id is off, the Settings LLM-test console surfaces the exact API error so it's self-correcting.

## Backend changes

### New `app/worker/` package (unified job dispatcher — replaces scraper poller)
Avoids Chrome-profile contention (single process, one driver at a time, sequential jobs):
- `app/worker/dispatch.py` — `run_job(job)`: routes by `job.type` → scraper / enrich / score handler. Sets status pending→running→done/failed/blocked, progress, timestamps (mirrors existing poller logic in `app/scraper/__main__.py:cmd_poll`).
- `app/worker/enrich.py` — `run_enrich(business)`: Botasaurus opens `business.website`, extracts emails (regex + `mailto:`), socials (fb/insta/linkedin/x/tiktok links), tech_stack (heuristic: WP `/wp-content`, Shopify, Wix, React/Vue/Next via generator meta / script srcs). Upserts `enrichments` row with status `ok`/`empty`/`failed` (browser-only, so `needs_browser` unused). Skips businesses with no website.
- `app/worker/score.py` — `run_score(business, explain)`: calls rules engine; optionally `llm.explain_score(...)`; upserts `scores` row.
- `app/worker/__main__.py` — `poll` loop (picks any pending `scrape|enrich|score` job, dispatches) + `run`/`smoke-test` retained for scrape convenience.
- `app/scoring/rules.py` — deterministic 0–100 scorer returning `[{name, weight, raw, contribution}, …]`. Factors: has_website, has_phone, rating, reviews_count (log-scaled), has_emails, has_socials.
- **Refactor:** move the existing poll loop body from `app/scraper/__main__.py:cmd_poll` into `app/worker` (reusing `maps_task.run_query` for scrape). `app/scraper/__main__.py` keeps `run` + `smoke-test`.
- **`scripts/start_all.sh`:** change the `scraper` tmux window command from `python -m app.scraper poll` → `python -m app.worker poll`. (`stop_all.sh` already kills the whole session — no change.)

### New API routers (registered in `app/api/main.py` under `/api`)
- `app/api/enrichment.py`:
  - `GET /api/enrichments` (join businesses; filters: city, status, search, min_emails, page) 
  - `POST /api/jobs/enrich` body `{business_ids?: int[], filter?: LeadFilters, max?: int}` → creates `Job(type="enrich")`.
- `app/api/scoring.py`:
  - `GET /api/scores` (ranked desc; filters: city, min_score, has_llm, search, page)
  - `POST /api/jobs/score` body `{business_ids?, filter?, max?, explain?: bool}` → `Job(type="score")`.
- `app/api/settings.py`:
  - `GET /api/settings` — effective config (db host masked, scrape knobs, llm base_url/model, **key-present bool only — never the key**), + live counts (leads, jobs by status/type, enrichments, scores).
  - `GET /api/settings/queue` — job-queue health breakdown.
  - `PATCH /api/settings/scrape` — update editable knobs (delay_min, delay_max, daily_cap) persisted to new `runtime_config` table.
  - `POST /api/settings/llm-test` body `{prompt}` → `{ok, model, latency_ms, reply}` or `{ok:false, error}`.
  - `POST /api/settings/retry-failed` — re-queue failed jobs → `pending`.
  - `POST /api/settings/rescore-all` — enqueue a `score` job for all businesses.

### Live-editable scrape knobs (safe, minimal)
- New `RuntimeConfig` model (single JSONB row) + **Alembic migration** (the only schema change — `enrichments`/`scores` already exist).
- `app/config.py`: add `get_runtime_config()` merging `.env` defaults ← DB overrides.
- `app/scraper/politeness.py`: `polite_delay()`/`check_daily_cap()` read `get_runtime_config()` per-call (with fallback to settings) so edits apply to the **next job**. `headless` + `cooldown_hours` stay env-only (decorator-bound) and shown read-only — honest about what's live.

### Export enhancement (focused, additive)
- `app/api/leads.py export_csv`: add `columns` (CSV list, validated), `include_score`, `include_enrichment` params to join extra columns. Existing behavior preserved when omitted.
